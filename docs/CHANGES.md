# 보완 내역 및 검증

업로드한 원본 ZIP을 기준으로 수정했다. 원본 파일을 제거하지 않았다.

## 주요 변경

- 스킬 47개: 구체적인 사용/제외 조건, 단계별 작업, 완료 기준 추가.
- 에이전트 3개와 참조 문서: 역할, 근거, 검증 경계 보강.
- 설치기: 항목별 파일 소유권, 기존 state 마이그레이션, 공유 규칙·외부 스킬 보존.
- 삭제: 정확한 항목 선택, 의존성 보호, 훅 설정과 스크립트 제거.
- 업데이트: 도구별 설치 목록·버전 비교, 다른 도구로 팩이 확산되는 문제 방지.
- 변환: Codex 호출 정책 파일, Claude 경로 frontmatter, 안전한 문자열 직렬화.
- 훅: 도구별 입력/출력 처리, 명시 설정한 포맷터의 편집 파일 단위 실행.
- 진단: 모든 지원 도구의 중복, 파일/블록/훅 누락, 의존성, 버전 확인.
- dry-run: 예정 파일 목록과 도구별 토큰 견적, 쓰기 없음.
- 카탈로그 검증 및 실제 회귀 테스트 추가.
- eval: 7개 과제 준비, 행동 채점, 보고서, 실패/수정 fixture 자체 검증.

## 실행 결과

Linux / Node.js v24.19.0 환경에서 다음을 확인했다.

| 검증                                           | 결과                                                       |
| ---------------------------------------------- | ---------------------------------------------------------- |
| npm run typecheck                              | 통과                                                       |
| npm run validate                               | 59개 항목, 오류 0                                          |
| npm test                                       | Node 테스트 결과 27개 통과, 실패 0 (회귀 상위 테스트 포함) |
| npm run build                                  | 통과                                                       |
| node evals/run.mjs --self-test                 | 7개 결함 fixture 실패, 7개 기준 수정본 통과                |
| 빌드된 CLI --version / Codex 선택 설치 dry-run | 통과                                                       |

실제 AI 모델 비교, 실제 도구 앱 로딩, Windows/macOS 환경, 원본 저장소 CI, npm 배포는 수행하지 않았다. 외부 벤더 명령은 안내만 제공한다.

## 적용 전 확인

패키지·CLI·팩 항목 버전은 `1.0.0`으로 유지했다. 이 저장소의 `package.json`은 기존 배포 메타데이터(라이선스, 저장소, `files`)를 유지하고 `private`는 넣지 않았다. 상세 적용 및 상태 마이그레이션은 [MAINTENANCE.md](MAINTENANCE.md)를 참고한다.

## 재검토 결함 수정

- 상위 경로가 일반 파일인 경우 쓰기 전에 거부한다.
- 롤백 중 한 파일 복구가 실패해도 나머지 복구를 계속하고, 원래 실패와 복구 실패 경로를 함께 보고한다.
- 기존 파일의 권한을 재작성 및 복구 시 보존한다.
- 공유 규칙 변경 시 관리 블록 밖의 들여쓰기·빈 줄·후행 공백을 보존한다.
- 평가 통과는 정상 종료와 검증 완료 신호를 모두 요구한다. 제출물의 조기 종료는 통과로 처리하지 않는다.
- 추가한 6개 회귀 사례는 수정 전 실패를 확인했고, 수정 후 통과했다.
