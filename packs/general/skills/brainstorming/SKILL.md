# Brainstorming

## Workflow

1. Read the relevant feature, constraints, and existing decisions. State the goal and non-goals.
2. Ask only questions whose answers change behavior, scope, or architecture. Reuse decisions the user already made.
3. Compare two or three feasible options against the same constraints; recommend one with its tradeoff.
4. Record the chosen behavior and acceptance checks. Ask for a decision only if a consequential choice remains; then hand off to writing-plans or implement-change.

## Completion

A short design decision with assumptions, rejected alternatives, and acceptance checks. Do not start implementation while the design remains unresolved.
